# Information Architecture and Systems Thinking

## Why this matters

Enterprise products often contain many roles, objects, workflows, and rules. Information architecture makes the system understandable by organizing content, navigation, labels, and relationships around user tasks.

## Core concepts

- **Content inventory:** A catalog of the product's content, features, and objects.
- **Taxonomy:** The labels and categories used to classify information.
- **Navigation model:** How users move between areas and return to important places.
- **Task flow:** The actions needed to finish a specific goal.
- **User journey:** The end-to-end experience across steps, channels, and touchpoints.
- **Card sorting and tree testing:** Methods for validating categories and findability.

## Think through

1. What are the top tasks for each user role?
2. Which concepts belong together in the user's mental model?
3. Are labels specific, consistent, and understandable without internal jargon?
4. Can users find critical work from more than one sensible entry point?
5. What should remain visible while users complete a multi-step task?

## Practice

Choose an admin dashboard. Inventory its main objects and actions, then propose a navigation hierarchy for an administrator and a day-to-day operator.

## Deliverable

Create a site map, two task flows, and a short rationale describing the navigation and labeling decisions.

## Common interview questions

### How would you improve navigation in a complex enterprise product?

I would first understand the main roles, their highest-frequency tasks, and the vocabulary they use. I would inventory the current structure, review search and navigation data if available, and validate proposed labels and groupings with card sorting or tree testing. The goal is not a single perfect hierarchy; it is helping each role find and complete important work reliably.

### What is the difference between a task flow and a user journey?

A task flow describes the steps a user takes to complete one goal inside a product. A user journey is broader: it includes stages before, during, and after the product interaction, plus user thoughts, pain points, channels, and opportunities. I use task flows to refine interaction behavior and journeys to identify system-level improvements.

## Key terms / cheat sheet

- **Taxonomy:** A system for grouping and naming content.
- **Findability:** How easily users can locate information or functionality.
- **Tree testing:** Evaluating navigation labels and hierarchy without visual design.

## Scenario challenge

Three roles use the same operations platform but report that its navigation is confusing. Create a plan to inventory content, validate labels, and define role-based entry points.

## Common pitfalls

- Organizing navigation around the company org chart instead of user tasks.
- Using internal jargon that users do not recognize.
- Treating search as a substitute for coherent navigation.

## Review checklist

- [ ] Top tasks and objects are clear for each role.
- [ ] Labels are consistent, specific, and validated with users.
- [ ] Navigation supports both frequent tasks and recovery from wrong turns.

## Portfolio evidence

Include the content inventory, site map, task flows, validation method, and rationale for key structural choices.

## Flashcards

**Q:** What is a taxonomy?  
**A:** A consistent set of categories and labels used to organize information.

**Q:** What does tree testing evaluate?  
**A:** Whether users can find items in a proposed hierarchy based on labels and structure.
